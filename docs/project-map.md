# Project map

Start with the area that owns the change. This map provides navigation; system
boundaries live in [architecture](architecture.md), placement rules in
[code organization](code-organization.md), and implementation conventions live in
[coding standards](coding-standards.md).

| Area                            | Start here                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Startup and assembly            | [CLI](../src/cli.ts), [configuration](../src/config.ts) (its base URL rule in [base-url.ts](../src/base-url.ts) is shared with setup), and [composition root](../src/app.ts). Shared vocabulary: [problem.ts](../src/problem.ts) for expected failures and [library.ts](../src/library.ts) for requested songs, library tracks, candidate matches, and remote playlists.                                                                                                                                                                                                                                                                                           |
| Interactive setup               | [src/setup/](../src/setup/) for the `setup` subcommand: [run.ts](../src/setup/run.ts) orders the steps and [flags.ts](../src/setup/flags.ts) parses the non-interactive flags. [steps/](../src/setup/steps/) holds each step ([navidrome.ts](../src/setup/steps/navidrome.ts), [audiomuse.ts](../src/setup/steps/audiomuse.ts), [clients.ts](../src/setup/steps/clients.ts)), which verify settings through the injected [prompt interface](../src/setup/prompts/prompts.ts) that [terminal.ts](../src/setup/prompts/terminal.ts) implements; [install/](../src/setup/install/) holds the server entry and the [add-mcp adapter](../src/setup/install/add-mcp.ts). |
| Tool contract and MCP transport | [src/tools/](../src/tools/) for the public contract ([inputs.ts](../src/tools/inputs.ts), [outputs.ts](../src/tools/outputs.ts)) and dispatch ([service.ts](../src/tools/service.ts)); [src/mcp/](../src/mcp/) for registration, descriptions, annotations, and result mapping.                                                                                                                                                                                                                                                                                                                                                                                    |
| Playlist workflows              | [src/playlists/](../src/playlists/): [publication.ts](../src/playlists/publication.ts) publishes drafts and recovers creation; [updates.ts](../src/playlists/updates.ts) owns existing-target append, refresh, and reconciliation. [records/](../src/playlists/records/) holds drafts and operation journals; [rules/](../src/playlists/rules/) holds matching.                                                                                                                                                                                                                                                                                                    |
| External integrations           | [src/navidrome/](../src/navidrome/) for the Navidrome adapter; [src/discovery/](../src/discovery/) for recommendation, expansion, and calibration workflows ([service.ts](../src/discovery/service.ts)), with the AudioMuse client in [adapters/](../src/discovery/adapters/), results and calibrations in [records/](../src/discovery/records/), and cutoff logic in [rules/](../src/discovery/rules/).                                                                                                                                                                                                                                                           |
| Persistence                     | [src/database/](../src/database/) for storage, typed schema, and migration execution; [drizzle/](../drizzle/) for reviewed SQL upgrades.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| Behavior tests                  | [tests/integration/](../tests/integration/) for public service workflows and upgrades; [tests/e2e/](../tests/e2e/) for stdio and process lifecycle; [tests/support/](../tests/support/) for shared fixtures.                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Domain and decisions            | [GLOSSARY.md](../GLOSSARY.md), [docs/adr/](adr/), and [agent guidance](agents/).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |

For specs and issues, follow [tracker conventions](agents/issue-tracker.md) before
accessing the local tracker.

The [pack smoke test](../scripts/pack-smoke.ts) verifies the published artifact:
CI packs the build, installs the tarball in a clean directory, and completes the
MCP `initialize` handshake on Linux, macOS, and Windows.
Pushing a `v*` tag publishes to npm; see [releasing](releasing.md).

For tooling, use [package.json](../package.json) and [.nvmrc](../.nvmrc) for runtime
and dependency requirements, [TypeScript](../tsconfig.json) and
[build configuration](../tsconfig.build.json) for compilation,
[ESLint](../eslint.config.js) and [Prettier](../.prettierrc.json) for mechanical
rules, and [Vitest configuration](../vitest.config.ts) for test projects.
[package.json](../package.json) also defines the published npm package;
the [README](../README.md) owns setup and usage.

Update this map when these entry points move or their responsibilities change.
Use the code and active feature spec to establish supported behavior rather than
maintaining a second feature inventory here.
