# Domain docs

## Before exploring

This repo uses a single-context layout:

- Read `GLOSSARY.md` at the repo root.
- Read relevant architectural decision records in `docs/adr/`.

If these files or directories do not exist, proceed silently.
The `domain-modeling` skill creates them lazily when terms or
decisions are resolved.

## Use the glossary's vocabulary

Use the glossary's terms when naming domain concepts in issues,
proposals, hypotheses, and tests.

For an undefined concept, reconsider whether it belongs in the
project's vocabulary. Note genuine gaps for `domain-modeling`.

## Surface ADR conflicts

When a proposal contradicts an existing ADR, identify the ADR and
explain why the decision should be reconsidered.
